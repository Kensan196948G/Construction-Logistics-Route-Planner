risk features are PoC sample data; the UI, reports, and API responses display a
persistent "本番利用禁止（PoC・サンプル）" notice (2026-08-05 evaluation
response, P0).

## Implemented Scope

### Backend
- FastAPI application with health, project CRUD, route generation, route evaluation, route risk, report (Markdown/CSV), data source, and knowledge search endpoints.
- **Persistent storage**: SQLAlchemy 2.0 async ORM with 14-table schema (users, projects, project_locations, vehicle_conditions, route_candidates, route_segments, route_risks, risk_comments, data_sources, data_source_fetch_logs, public_geo_features, knowledge_points, reports, audit_logs). Default SQLite via aiosqlite; PostgreSQL via asyncpg when `DATABASE_URL` is set.
- **Alembic migrations**: autogenerated initial schema with forward/backward migration verified.
- **Authentication**: OIDC (Entra ID) JWT validation via python-jose with automatic API key fallback when `ENTRA_TENANT_ID` is not set. Role-based access control (admin / planner / site_user / viewer, 4 roles). Production mode is fail-closed: `PRODUCTION_MODE=1` without any configured auth returns 503 instead of open access, and OIDC without `ENTRA_CLIENT_ID` also fails closed. API-key comparison uses `hmac.compare_digest`.
- **Spoof-resistant audit identity**: API-key mode derives identity from deployment config (`APP_API_KEY_USER_ID` / `APP_API_KEY_USER_ROLE`) instead of trusting `x-user-id` / `x-user-role` headers; unauthenticated operations are recorded as `anonymous`.
- **Durable audit logging**: all API operations logged to `audit_logs` table with user, role, action, IP, and user-agent; admin CSV export (`/api/admin/audit-logs/export`) with formula-injection neutralization.
- **External API adapter layer**: abstract `DataSourceAdapter` base class with `OSMOverpassAdapter` (stub), `XROADAdapter` (stub), `PLATEAUAdapter` (stub), `KSJAdapter` (stub), and `AdapterRegistry`.
- **Sample-data disclosure**: persistent UI banner, report watermark (Markdown/CSV), and API metadata (`sample_mode`, `sample_data_notice`) so sample output is never mistaken for production data.
- **Minimal RBAC (4 roles)**: `admin` / `planner` / `site_user` / `viewer` with endpoint-level enforcement; approve/audit are admin-only, confirm is open to planner/site_user/admin.
- **Confirmation & approval workflow**: risk confirmation (`confirmed` / `needs_review` / `not_applicable`), project submit → approve / request-changes, all audited in `audit_logs`.
- **Real routing adapter (OSRM)**: `ROUTING_PROVIDER=osrm` returns real road-network candidates (distance/duration/geometry) with fallback to sample on failure.
- **Real OSM feature adapter (Overpass)**: `OSM_OVERPASS_ENABLED=1` fetches bridges, tunnels, schools, and hospitals with source URL + attributes, cached for 6h.
- **PostGIS foundation**: Alembic migration enables the PostGIS extension on PostgreSQL; docker-compose ships a `postgis/postgis:16-3.4` service with `DATABASE_URL` wiring.
- **PDF reports**: `GET /api/projects/{id}/report?format=pdf` renders the initial-review memo (Japanese CID font).
- **Delivery/avoid persistence**: delivery date, time window, holiday, night-delivery flag, and avoid conditions are persisted (additive migration) instead of being dropped; project owner identity is recorded from the authenticated user.
- **Route regeneration history**: `route_candidates.generation` keeps old batches as an audit trail; list/report views expose only the latest generation, and risk confirmation statuses carry over across re-evaluations.
- **Security hardening**: security headers (CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy), knowledge-search rate limit (30/min/IP), CSV formula-injection protection, and Entra JWKS cache with TTL + refresh-on-kid-miss.
- **Backup/monitor/restore scripts**: `scripts/backup_db.sh` (SQLite or pg_dump), `scripts/restore_db.sh`, `scripts/monitor.sh`.
- **API-level E2E**: fictional-site flow from project input through evaluation, confirmation, approval, and PDF output.

### Frontend
- Nine-screen single-page UI implementing the Claude Design handoff (`Route Planner.dc.html`): dashboard, project/conditions, route review & map, risk memo, report output, knowledge search, facilities dictionary, admin, and system settings.
- Self-contained client runtime (`app/static/dc-runtime.js`) that interprets the design-component template dialect.
- Real interactive basemap: vendored Leaflet + OpenStreetMap tiles.
- **Live API integration**: project creation, route generation, route evaluation, and report fetching call the backend API. Falls back to demo data when API is unavailable.
- **Loading/empty/error states**: `apiLoading`, `apiError`, `apiOnline` state flags with graceful degradation.

## Known Limitations

- External API adapters (xROAD, PLATEAU, KSI) are stubs; real API keys needed.
- Cloudflare deployment requires `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`.
- Neon PostgreSQL provisioning requires Neon API key.
- Entra ID tenant configuration requires `ENTRA_TENANT_ID`, `ENTRA_CLIENT_ID`.
- OSRM/Overpass public servers are for low-volume evaluation only; production must self-host or use a commercial routing/GIS API.
- The knowledge search is a deterministic, rule-based responder, not a live LLM.
- Playwright screenshot validation not available in this environment (SIGTRAP).
- Real xROAD/KSJ/PLATEAU integration remains a Phase 2 item (adapter layer ready,
  API keys/contracts pending).
- Browser E2E runs on Firefox headless: Chromium/Chrome crash immediately
  (SIGTRAP) in the development environment.
